# Changelog

## v1.3.3

- **India carrier config also fixes Samsung Wallet and the 6 GHz hotspot** (`india`). `hotspot6g` enables the 6 GHz band by setting `ro.csc.countryiso_code=IN`, but on a non-Indian model (e.g. the Canadian SM-S918W) that makes Samsung's server reject the phone: Samsung Wallet showed "there's a problem with Google Play services" and India features (UPI, DigiLocker, transit) were gated off, because the server saw an inconsistent model + country. `india` now also runs `resetprop` so the phone reports itself as the Indian S23 Ultra (model `SM-S918B`, sales code `INS`, country `IN`). The server then accepts it, so Samsung Wallet India and the 6 GHz hotspot both work. Runtime only: it reverts on reboot and writes none of the CSC files (no factory-reset risk). While on, the reported model changes for every app, and adding bank payment cards may still fail (that path checks the real model by hardware attestation). If Samsung Wallet still shows "not supported" after applying (it caches the earlier rejected state), clear its storage (Settings > Apps > Samsung Wallet > Storage > Clear data) and reopen. Verified on an SM-S918W (XAC): Samsung Wallet went from "not supported" to opening with UPI, and the enabler returned full `spay` support.

## v1.3.2

- **Call recording on any sales code** (`callrec`). It used to run only on XAC (S918WVLU8GZIF) and EUX (S918BXXUAGZIF), with a decoded copy of each firmware's `cscfeature.xml` in the module and an MD5 check on the stock file. The module now decodes the phone's own stock file at every apply (new `files/omcdec`, a static arm64 build of `src/omcdec`, using the `SemCscFeature` tables), adds the two recording keys to every `FeatureSet` and binds that. The folder comes from `mdc.system.path`, so "single" multi-country layouts work too. On XAC this drops the Smart IVR and message card keys the old file also had; `india` still has them. Tested off the phone: on the stock XAC file it gives the same result as the old file without those two keys, and on EUX the same as the old EUX file. Not yet tested on a phone.
- **India carrier config on any sales code** (`india`). The INS files now go over whatever sales code's files the phone uses (One UI 9 only, since they come from S918BXXUAGZIF). The INS keystrings are copied under the phone's own sales code's name. Its prism folder keeps the phone's `sales_code.dat`. Not yet tested on a phone other than XAC.
- **HideKSU for SM-S918B INS and SM-S918U1** (`hideksu`). Patched `services.jar` payloads for two more stock jars. Each phone downloads only the one that matches its own jar's MD5 (`HIDEKSU_JARS`, `hideksu:<md5>` lines in `PAYLOADS`). New `tools/hideksupatch.sh` makes the payload for any stock jar; it rebuilds the S918W one with byte-identical dex files. The INS and U1 dex files differ from the S918W ones only in the header hash and a build-number string. Not yet tested on those phones.

## v1.3.1

- **Horizontal lock levels small tilts, in the viewfinder too** (`camextras`; issue #8). v1.3.0's patch switched the recording stabilizer's levelling on, but the stabilizer clamps the correction to a per-sensor maximum from the S23's EIS tuning: 8°, since the S23 never shipped horizontal lock. So a 30° tilt still showed 22° and the picture seemed to turn with the phone. The module now also binds a copy of the stabilizer (`com.qti.eisv3.so`) whose 16 reads of that maximum become 30°, and does the same for the preview's separate stabilizer pair (EIS v2: a patched node that switches levelling on for Super steady = 2, and `com.qti.eisv2.so`), so the viewfinder levels as well. All are found by instructions; a part that doesn't match is skipped and the log says what that leaves. Limits, measured with the gyroscope against the video: the crop margin Super steady reserves (about 20%) caps the applied correction at roughly 20° on the ultrawide, the correction is smoothed so it trails quick moves, and Qualcomm's levelling snaps to the nearest 90° orientation. It is not the S26's 360° horizontal lock. On the main (1×) camera the margin is too small for it to show. Tested on S918WVLU8GZIF: at tilts up to about 15° the recorded horizon stays within a few degrees (it followed the phone at about 0.75× before), with no artifacts.
- **Opt-in for custom kernels** (`airdrop`, `wifi7`; issue #10). AirDrop and Wi-Fi 7 only ran on Samsung's own kernel for the supported GZIF builds. On one of those builds with another 5.15 android13 kernel, creating `/data/adb/s23tweaks/allow-any-kernel` now lets them try. The kernel still checks every symbol CRC (`CONFIG_MODVERSIONS`) and refuses the modules if one differs; the module then puts the stock Wi-Fi driver back, as it does for any failed load. Untested: I only have a stock kernel.

## v1.3.0

- **24 FPS in standard Video** (`cam24fps`, new; PR #11 by moesuito). Samsung Camera offers 24 fps only in Pro video. `cam24fps` adds `video` to the FHD, UHD and 8K 24 fps entries in `camera-feature.xml` (every other attribute kept) and binds a byte-patched copy of `SamsungCamera.apk` whose standard-Video allowlist (`te.f0.i`) gets UHD 24 and FHD 24 in two slots only Fold/Flip models use (8K 24 is already listed). QHD stays hidden. The patch is in `device/files/`, made by `tools/cam24patch.py`. The tweak goes by the stock `SamsungCamera.apk` itself, not the firmware name: it runs on any phone whose Camera APK has a known MD5, and checks the patched copy's MD5 too. So far that covers the 17.0.00.43 APKs of S918BXXUAGZIF and S918WVLU8GZIF, which differ in MD5 but take the same patch bytes (uninstall Camera updates first). Tested by the contributor on S918BXXUAGZIF (24 fps in FHD, UHD and 8K, with Log video, lens switching while recording) and on S918WVLU8GZIF: FHD, UHD and 8K clips record at 24/1 fps, and Log video, horizontal lock and photos still work with no Camera crashes.
- **AirDrop finds Apple devices again after Mosey updates itself** (`airdrop`). Google Play now pushes Mosey updates (1.0.927074190 → 1.0.980159239). The new Mosey checks for its native service (`IMoseyService`) once at boot and disables its own `ExternalSharingService` if it isn't there yet, which it never is, because the module starts `mosey_server` at the end of the apply. Play services then started its provider registry but found no provider, and Quick Share never listed iPhones or Macs (`isExternal=false`). The module now enables the service right after `mosey_server` registers. Verified on S918WVLU8GZIF after a full reboot: the service comes up enabled with no manual step, and the iPhone and Mac show up in Quick Share.
- **SmartSuggestions no longer crashes during the apply** (`galaxyai`, also `colortone`, `settingssearch`). The S24 APKs were bound about 30 s before the framework restart, ahead of the camera driver restarts. Any app process started in that window used the stock APK's parsed manifest with the new APK and crashed (`Failed to parse XML configuration from Canadian_dollar`): about 5 crashes per apply. The APKs are now bound just before the restart (a 1.2 s window); the library binds stay where they were. Verified on S918WVLU8GZIF: no crashes on a full boot apply, and all three tweaks still on.
- **HideKSU goes by the framework file, not the firmware name** (`hideksu`). It used to run only when the firmware was S918WVLU8GZIF. It now runs on any phone whose stock `/system/framework/services.jar` has the same MD5 as the one the patch was made from, and it checks the downloaded patched jar's MD5 before binding it. Its status also said "bound, waiting for a framework restart" forever: `system_server` runs the patched jar's code from memory, so the jar never shows in its memory map. It now reports on once `system_server` has restarted since the bind. Verified on S918WVLU8GZIF: the stock check passes, the status reads on after the restart, and CRED runs without crashing.

## v1.2.9

- **HideKSU: root-aware apps stop crashing** (`hideksu`). Apps like CRED kill themselves on launch when the KernelSU manager (`me.weishu.kernelsu`) is installed — their native anti-tamper enumerates installed packages through the package manager (CRED's `libSecureComponent.so` calls `getPackageInfo`), and a sandboxed app has no other way to see another app. `hideksu` binds a patched `services.jar` whose `AppsFilter` hides the manager from any third-party caller (appId ≥ 10000), except `df.root` (so DFRoot still loads root at boot) and the Samsung launcher (so the manager icon still shows). Nothing is injected into the apps, so their own `/proc/self/maps` scans stay clean — unlike an LSPosed/Zygisk module, which they can catch. The manager stays installed, so there's no more uninstall-before-you-use dance. Verified on S918WVLU8GZIF: with the KernelSU manager installed, CRED went from crashing every few seconds (NFC kept restarting its payment service) to running normally; the manager icon and root at boot both kept working. Needs firmware S918WVLU8GZIF (the patched `services.jar` is built for that exact build) and the KernelSU manager installed; applies on a framework restart.

## v1.2.8

- **Much less CPU with AirDrop on** (`airdrop`). The guard that reboots the phone cleanly if the Wi-Fi firmware crashes read the whole kernel log (about 260 KB) every second to look for the crash line. On an idle phone that was about a third of all CPU time: 2.86 s of CPU every 30 s, about 18 minutes of CPU in 3.4 hours. It now waits on `dmesg -W`, which blocks until the kernel logs something new: 0.02 s per 30 s. Measured on S918WVLU8GZIF. Phones keep the old guard until they reboot after updating the module.
- **Always On Display brightness follows the room light** (`display`). The AOD app builds its brightness from two framework tables (`config_autoBrightnessLevels_doze`, `config_autoBrightnessDisplayValuesNits_doze`) that the S23 ships empty, so every light reading logged "getBrightnessValues not matched!" and the AOD got 0 nits: it sat at its minimum, and the lock screen wallpaper on AOD showed bright for a few seconds and then dropped sharply. `display` now adds the S24 Ultra's two tables with a small static overlay (`files/aodbright.apk`, built from `src/aodbright`) layered onto `/product/overlay`, and restarts the framework. Samsung's package manager doesn't list the overlay ("not in allowed list"), but zygote loads it into every app's system resources, which is where the AOD app reads it. Tested on S918WVLU8GZIF: at 13 lux the AOD went from 0 to 14.5 nits. Not yet checked in bright light.

## v1.2.7

- **AirDrop loads after hours of uptime** (issue #7). Applying `airdrop` long after a reboot could fail with "Failed to register mac80211 hardware. Ret: -12": mac80211 needs one 128 KB block of contiguous memory for its transmit queues, and the kernel gives up on a block that large once memory is fragmented. `wonder.ko` now asks for a block that size first in a way that makes the kernel reclaim and compact until it gets one, and frees it just before registering. Tested on S918WVLU8GZIF at 2.6 hours uptime: the old `wonder.ko` failed 6 times in a row, the new one loaded first time. If it still fails, `tweaks.sh` compacts memory and retries twice. The AirDrop download is now `airdrop-S918WVLU8GZIF-2.tar.gz` (only `wonder.ko` changed).
- **Re-applying after a failed AirDrop load no longer swaps the Wi-Fi driver again.** When the S24 driver and firmware are already in and only `wonder` is missing, the apply loads just `wonder`. Before, each retry dropped Wi-Fi, stacked another firmware overlay and could fail with "firmware overlay".
- **Bug reports show whether Galaxy AI's secure storage is blocked** (issue #5). Now Brief's Personal Data Intelligence keeps its data in Samsung's Pass Storage, and Android refuses to create it ("Root detected", then a "creation failed" crash loop) when the system process can see an `su` file at one of a dozen classic paths (`/system/bin/su`, `/system/xbin/su`, `/data/local/su`, ...). With KernelSU, `/system/bin/su` shows up for apps granted root, so this happens when something running as the system user has root, or a module leaves an `su` file. The report now lists the `su` files the system process sees and the last Pass Storage log lines.

## v1.2.6

- **`callscreen` installs Samsung Language Core again.** It streamed the 3.1 GB APK into `pm install -S <size>`, whose size is a 32-bit number, so every install failed with "Failed transaction". It now installs a temporary copy from `/data/local/tmp` (needs 3.5 GB free for a minute). With Language Core 4.0.01.24, Call screening's **AI summary works**; the README said it didn't, from a test with another build.
- **Super steady's horizontal lock levels the horizon** (`camextras`). Until now the option showed up but the picture still turned with the phone: the S23's camera driver treats it as plain Super steady. Its stabilizer (Qualcomm EIS v3) can level the horizon, but the S23 build never switches it on (it reads the wrong tag). `camextras` now patches 8 instructions in a copy of the phone's own EIS library so horizontal lock turns levelling on, and binds the copy from storage; the camera driver restarts once during the apply. The code is found by its instructions, so other firmware with the same code works too; if it differs, the option still shows but won't level, and the log says so. Tested on S918WVLU8GZIF.

## v1.2.5

- **Gallery's Log color correction works** (`logvideo`, issue #3). On One UI 9 it's Edit → LUT in Samsung's video editor, which reads the LUTs from `/data/vendor/LogVideofilters`. That folder is empty on the S23, and the S23's SELinux policy wouldn't let the editor read files there anyway, so the LUT loaded with no data and the video stayed flat. `logvideo` now downloads the S24 Ultra's 10 Log LUTs and their thumbnails (30 MB) and binds them over the folder with a label apps can read. Tested on S918WVLU8GZIF with Standard and Blockbuster.
- **Bug reports say more.** New sections: the screen's colour state (screen mode, SurfaceFlinger colour mode, native mode, panel white point), AirDrop and Wi-Fi (Wi-Fi standard, the driver's kernel-log lines, Mosey and Quick Share warnings and errors with names in quotes masked) and every apply in the current boot from the kernel log. App crashes are grouped by app and error, like native crashes.
- **The apply log says which build wrote it** (module version, model, firmware, CSC, kernel) and names tweaks that are still on from an earlier apply in the same boot although they weren't picked this time (binds, kernel modules and properties stay until a reboot).
- **`status`**: the `features` line no longer shows the battery tweak's flag, and the AirDrop line says whether the Mosey service is registered instead of a bare "found".
- **Vivid screen mode has its colours back** (`display`). The tweak also turned on the S24's Vividness slider (`LCD_CONFIG_VIVIDNESS`, `LCD_CONFIG_VIVIDPLUS`). With `VIVIDPLUS` on, Vivid mode switched SurfaceFlinger from the panel's wide colour gamut to sRGB, so colours looked washed out for as long as `display` was applied, whatever Adaptive color tone was set to. The slider itself never worked on the S23: it writes to a panel control the S23 doesn't have. Both flags are gone; `display` now only puts the lock screen wallpaper on Always On Display. Applying without them (or rebooting without the module) restores the wide gamut.

## v1.2.4

- **Bug reports in one tap**: Module page → Status → *Make a bug report* (or `tweaks.sh report`) saves a text file in Download with the phone model and firmware, what each tweak found, the stock settings the tweaks overwrite, the logs and recent crash summaries, and copies it for an issue. No serial number, email, MAC addresses or IMEI. Applies now also log the stock values they replace.
- **Camera settings are set, not just added** (`logvideo`, `camextras`): a camera setting the phone's own camera-feature.xml already had was left alone, so a model that ships `SUPPORT_LOG_VIDEO` as `false` would keep Log off while the tweak reported it on. The tweak now replaces such a line, and its status checks the value.
- **New tweak `tenbit`**: apps can record 10-bit HDR (HLG10) video with the front cameras. The S23's camera driver gave the 10-bit capability and profile list to rear cameras only, so Android refused 10-bit streams on the selfie cameras. The tweak finds the three places in the phone's own driver by their instructions (they match in One UI 6 and One UI 9 builds, at different offsets), patches a copy, and binds it from storage. It keeps the copy only if the camera driver stays up and a front camera then lists 10-bit; otherwise the stock driver goes back. Tested on S918WVLU8GZIF with a Camera2 app on front cameras 1 and 3: HEVC Main 10, BT.2020, HLG, with true 10-bit samples. Samsung Camera photo and video still work.
- **New tweak `hdr2023`**: the 2023 (One UI 6) ArcSoft hybrid HDR and bracketed HDR engines instead of today's, for anyone who prefers the older HDR look. 28 MB download; a Camera category or "all" pick leaves it out. Bracketed HDR is tested; hybrid HDR (ordinary daylight) isn't.
- **4K auto framing** (`autoframe`) works on SM-S918W: front camera, auto framing on, then Video size → UHD records 3840×2160. Auto framing keeps its own video size, which starts at FHD.
- **Log video no longer crashes the camera.** It turned on the LUT preview button too, and tapping it crashed Camera (the LUT preview is drawn by the S24's camera HAL; the S23's has no such code). The button is gone; Log recording is unchanged.
- **The lock screen wallpaper on AOD shows again** (`display`). v1.2.3 stopped setting `LCD_CONFIG_AOD_BRIGHTNESS_ANIMATION`, and without it the wallpaper can't be seen on AOD at all (tested on a phone). The flag is back, so the wallpaper again starts bright and dims sharply after a few seconds.

## v1.1.0

- **Categories:** the tweaks are grouped into Connectivity, Camera, Display and graphics, Galaxy AI and Samsung apps, Battery and settings, and Carrier. The module page has a checkbox per category (all, some or none), and the installer takes a category letter or single tweak numbers.
- New tweaks: `camextras` (Director's view and Super steady horizontal lock), `autoframe` (4K auto framing, untested), `settingssearch` (S24 Settings search bar, 10 MB download), `bargein` (Bixby barge-in, untested) and `callscreen` (Call screening via Samsung Language Core; screening works, the AI summary doesn't; persistent; 3.1 GB download in two parts).

All tweaks on now take 24 KB of tmpfs instead of about 107 MB. Programs bound from /data get `nosuid` cleared with BusyBox so they still enter their SELinux domains (the kernel won't build an overlay from /data).
- **Removing the module cleans up everything it made:** Play services flags, Language Core (if it installed it), the Camera setting, cached app manifests and `/data/adb/s23tweaks`. The cleanup (`tweaks.sh cleanup`) waits for Android and the first unlock.

- **The zip holds only scripts** (under 400 KB instead of 20 MB). Every tweak that needs files, `airdrop` and `wifi7` included, downloads them from the `payloads-S918WVLU8GZIF` release when it's applied, checked against SHA-256s pinned in `device/tweaks.sh`. A file split into parts (over GitHub's 2 GB limit) is joined on the phone.

- New tweaks: `display` (Vividness slider and full-screen AOD wallpaper), `logvideo` (Log recording and LUT preview in Pro video) and `vulkan` (Skia on Vulkan for apps).
- Feature flags can now be set to values, replacing the stock ones (not only added as TRUE).
- New tweaks with their own download, fetched by the phone only when picked: `camerahdr` (untested: puts back the multi-frame and low-light HDR camera processing One UI 9 removed), `audioeraser` (Audio Eraser in Gallery), `colortone` (Adaptive color tone) and `galaxyai` (S24 Now Brief, Creative Studio and Call Assist).

## v1.0.0

First release, for the Galaxy S23 Ultra on One UI 9 / Android 17 (AirDrop and Wi-Fi 7 need firmware S918WVLU8GZIF).

- Seven tweaks: AirDrop with Apple devices, battery health page, extra settings (auto power on/off, louder VoIP calls), call recording, India (INS) carrier config, 6 GHz Mobile Hotspot, Wi-Fi 7 multi-link (MLO).
- KernelSU module with a settings page: install from KernelSU → Modules, pick tweaks and apply on the phone, no computer needed.
- Apply at every boot: the saved tweaks re-apply automatically after each reboot, with fail-safes against boot loops.
- Computer installer (`install.sh`) over adb for macOS and Linux.
- Nothing is written to a partition; a reboot returns the phone to stock.
